Evals only catch the failures you already thought of. The expensive ones are the failures you didn't — and today the only way to find those is an engineer reading traces by hand until they get bored. sift reads them, groups what it finds into themes that keep their names, and tells you which one got worse since you shipped.

A theme is an issue, not a chart

Clustering dashboards fail for two reasons: the labels rename themselves every week, and re-clustering gets more expensive the longer you run it. sift discovers once, then assigns — so SIFT-14 means the same thing next month, which is the precondition for tracking anything at all. 

$ sift resolve SIFT-20 --note "fixed in v1.3"
SIFT-20 is now resolved

# ... the next release ships ...

$ sift check --fail-on regression

  ✗ sift check failed — 1 finding

    REGRESSED  SIFT-20  retry loop on search_kb
      2.0% → 15.0% between v1.2 and v1.3

$ echo $?
1

A theme you marked resolved picking traffic back up is a regression in Sentry's sense of the word — and it exits non-zero, so the build stops. Discovery that can't fail a build stays something somebody has to remember to go and look at.

Regressions only, by default. Gating on anything new would turn every release red and teach the team to ignore the gate.

sift export SIFT-20 --format mastra-scorer then turns that theme into eval cases seeded from the real traces in it. Discovery → known failure → regression test.

How it works

The technique comes from Anthropic's Clio: raw traces are too long and too noisy to embed, so a model writes one-line summaries along a few fixed dimensions and those get clustered instead. sift adds the parts that make it a tool rather than a demo.

Assignment, not re-clustering

One embedding and one cosine per new trace. Clustering only runs at bootstrap and on the residual pile, so steady-state cost stops growing with your history.

Stable ids and a lifecycle

new → active → regressed / resolved / muted. The identity is what makes tracking, alerting and accountability possible.

Deltas, not snapshots

Each change is scored against that theme's own historical variance — a theme that swings 10 points weekly hasn't done anything by swinging 10 points again.

OTel-native

GenAI semantic-convention spans from Mastra, Langfuse, Phoenix, OpenLIT or raw OTLP. Point an exporter at sift serve and it collects.

Local-first, gated

One SQLite file, zero runtime dependencies, embeddings can run locally. Summaries bound for a hosted model get emails, cards, IPs and keys rewritten first.

Honest about its limits

The README says what isn't built and what isn't verified, including where the offline embedder falls down. Measured, not asserted.

Try it without an API key

The offline providers run the whole pipeline — ingest, summarize, embed, discover, delta — with no network and no key.

$ export SIFT_LLM_PROVIDER=fake SIFT_EMBED_PROVIDER=hash
$ sift demo --out ./traces.jsonl   # synthetic traffic, planted failures
$ sift analyze --otlp ./traces.jsonl
$ sift serve                       # the dashboard, on localhost
