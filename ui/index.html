Sentry-grade issue tracking for agent behavior.

Your agent produces thousands of traces. Nobody reads them. Your evals only catch failure modes you already knew about — the expensive ones are the failures you didn't anticipate. sift reads the traces for you, groups what it finds into stable, trackable themes, and tells you what changed since your last deploy.

$ sift analyze --since 7d

  ▸ SIFT-3   user asks for refund, agent deflects   8.4%   (± 0.3%)   active

  ▸ SIFT-7   billing questions resolved first-try  31.0%   (↑ 2.2%)  active

  ○ residual pile: 118 traces (5.0%) — discovery will re-run at 8%

How it works

The technique comes from Anthropic's Clio: don't cluster raw traces, they're too long and too noisy to embed. Have a model write one-line summaries along a few fixed dimensions, then cluster those. sift adds the parts that make it a tool rather than a demo.

Classification-first

Clustering runs at bootstrap and on the residual pile only. After that, themes live in a persistent registry and each new trace is assigned by nearest centroid — one embedding, one cosine. Labels stop renaming themselves weekly, and cost stops growing with your history.

Themes have a lifecycle

A theme gets a stable id and a state machine: new → active → regressed / resolved / muted. Like a Sentry issue, not like a chart. That identity is what makes tracking, alerting and accountability possible at all.

Deltas, not snapshots

The question is never "what are my themes." It's "what changed since Tuesday's deploy." sift diffs theme distributions across releases and scores each change against that theme's own historical variance.

It can block a deploy

sift check --fail-on regression exits non-zero when a theme you'd marked resolved picks traffic back up. Regressions only by default — gating on anything new would turn every release red and teach everyone to ignore the gate.

Closes the loop into evals

sift export turns a failure theme into eval cases seeded from the real traces in that cluster. Discovery → known failure → regression test → resolved. That loop is the product; the clusters are just the intake.

Local-first, gated

One SQLite file, zero runtime dependencies, embeddings can run locally. When summaries do go to a hosted model, a pseudonymization pass rewrites emails, cards, IPs and keys first. Traces are the most PII-dense artifact you produce.

Try it without an API key

The offline providers run the whole pipeline — ingest, summarize, embed, discover, delta — with no network and no key.

$ npm install -g @siftlabs/sift

$ export SIFT_LLM_PROVIDER=fake SIFT_EMBED_PROVIDER=hash
$ sift demo --out ./traces.jsonl   # synthetic traffic, planted failures
$ sift analyze --otlp ./traces.jsonl
$ sift serve                       # the dashboard, on localhost

Requires Node 22.18+. The package name is a placeholder scope until the first publish — build from source in the meantime.
